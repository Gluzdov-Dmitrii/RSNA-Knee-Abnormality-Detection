# Стратегия публикации весов и inference для RSNA Knee

Проверено 10 сентября 2026: локальные исходники и результаты Grok, live SSH
на ngpu01, Kaggle API и публичные исходники участников. Это предложение следующей
работы, а не запуск обучения, изменение плана Grok или разрешение submission.

## Решение

Основная ставка для сильной публикации: собственные обученные веса на основе
воспроизводимого Raptor/CoAtNet-рецепта, с одним проверяемым улучшением — обучением
на согласованных слабых метках вместо одного источника. Публиковать полный
inference и training/rebuild рядом с весами. Не переупаковывать чужие checkpoint
под видом своей модели и не выдавать прежний 0.937 ансамбля A0 за качество новой NN.

Работу Grok сохранить как независимую компактную ветку и дешёвую экспериментальную
площадку. Сначала закончить уже идущий R(2+1)D и измерить лучший существующий
собственный checkpoint отдельно. Не продолжать бесконечную смену backbone ради
круглого weak-label OOF 0.85: соответствие такого порога LB ещё не установлено.

## Что реально получено у Grok

| Вариант | Локальный macro AUC по Pilkwang | Что это доказывает |
| --- | ---: | --- |
| S22 ResNet18 2.5D | 0.768331 | Собственная обученная ветка |
| S22 regularized | около 0.757 | Эта регуляризация не улучшила контроль |
| S22 MLP head | около 0.769 | Почти тот же результат |
| S23 ConvNeXt-Tiny | около 0.713 | Смена архитектуры сама по себе не помогла |
| S24 r3d18, 9 срезов | 0.800641 | Лучший завершённый отдельный pixel-контроль |
| S25 S22+S24 rank mean | 0.805972 | +0.005331 к S24, но две ветки и пока один seed |

OOF — предсказания для исследований, исключённых из обучения соответствующей
модели. Таблица отражает validation с выбором лучшей эпохи на том же fold; это
полезная CV-оценка, но не полностью независимый финальный тест выбора checkpoint.
S25 оценивает 4,406 строк с метками; кэш содержит 4,407. Одна строка без меток
исключена из оценки, а не потеряна при конвертации.

Живой процесс на A100: PID 65638, R(2+1)D, 16,542 MiB (~16.2 GiB) VRAM. На момент проверки
fold 0 завершил обучение, fold 1 дошёл до эпохи 4 с val AUC 0.813775;
примерно 211 секунд/эпоху. Это не итоговый пятифолдовый результат. Процесс не
останавливался, новые GPU-работы не запускались.

В S24 около 99.5 млн параметров: три независимых r3d18. FP16 export занимает
199,186,242 байта на fold, 995,931,210 байт за пять. 11 GiB — размер обучающих
пикселей, не размер модели и не доказательство быстрого inference на T4.

Из проверенных прежних LB: A0/S01 0.937, 40%-overlay S22 в transformer-ветку A0
0.931. Последний результат нельзя называть standalone score S22. Новый S24 и
S25 ещё не имеют здесь подтверждённого LB. Реестры экспериментов отстают от
RESULT.md/metrics.json: S24/S25 местами всё ещё planned; для оценки использованы
конкретные результаты и исходники, а не только ledger.

## Наблюдения по коду, которые влияют на выбор эксперимента

- S22 фактически берёт только индексы 1/4/7 из девяти срезов каждого слота.
  S24 читает все девять. Поэтому +0.032 нельзя приписывать исключительно 3D:
  одновременно изменились используемые изображения и представление каналов.
- S24 складывает fluid, structural и их среднее в три канала. Между двумя
  разными сериями нет проверенной пространственной регистрации; одинаковый
  индекс среза не доказывает одинаковую физическую плоскость. Это допущение
  представления, а не установленная причина низкого score.
- Окно .35–.65 покрывает только центральную часть стека. Не путать его с crop
  130 mm внутри отдельного изображения. Сильные Raptor-рецепты используют гораздо
  более широкий диапазон срезов. Увеличить покрытие теми же девятью срезами можно
  без роста размера кэша, но нельзя восстановить периферию из уже готового кэша.
  Для нового окна требуется снова читать официальный DICOM и переобучать модель.
- Датасет возвращает значения 0–1 без нормализации, указанной для Kinetics weights.
  Это измеряемое отличие от pretrained-рецепта, а не доказанный баг: модель
  дообучается. Нельзя добавить нормализацию только в inference уже обученных весов.
- Аугментация определяется seed+index и повторяется для исследования каждую
  эпоху. Это снижает разнообразие по сравнению с новым случайным преобразованием
  каждый epoch; нужно отдельное сравнение, не обещание выигрыша.
- MixUp смешивает заполненные нулями отсутствующие метки и берёт максимум масок.
  Если один таргет неизвестен, это может внести ложный отрицательный вклад.
  При внедрении disagreement-масок нужен mask-aware loss, например взвешенная
  сумма двух masked losses с корректным знаменателем; иначе новый эксперимент
  проверяет смесь качества меток и ошибки обработки пропусков.
- Текущий slice-attention код использует один attention score на срез для всех
  диагнозов; у Raptor веса внимания отдельные для каждого диагноза. Это известный
  приём из исходного решения, не наша новая архитектурная идея.

Источники: `training/s22_resnet18_25d.py`, `training/s24_r3d18_9slice.py`,
`training/s24_slice_attn.py`, `ops/tools/pixel_dataset.py`,
`experiments/S22/RESULT.md`, `experiments/S24/metrics.json`,
`experiments/S24/export_manifest.json`, `experiments/S25/metrics.json`.
Нормализация pretrained: [Torchvision r3d18](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.video.r3d_18.html).

## Как публикуются другие

Снимок API, не обещание будущих votes. Поиск по «rsna knee» не исчерпывает все
модельные наборы, а скачивания нельзя трактовать как число уникальных пользователей.

| Публикация | Votes на момент API-проверки | Практический вывод |
| --- | ---: | --- |
| [Raptor weights](https://www.kaggle.com/datasets/dreaddevelopment/raptor-knee-widedense) | 65 | Собственный готовый MRI-reader, ~543 MB за два checkpoint |
| [Raptor inference](https://www.kaggle.com/code/dreaddevelopment/knee-mri-twelve-findings-from-a-single-model) | 123 | Один понятный модельный пакет, заявленный/отображённый LB 0.924 |
| [Pilkwang baseline](https://www.kaggle.com/code/pilkwang/rsna-knee-baseline-v1) | 546 | Ранний полноценный baseline решает задачу пользователя целиком |
| [Pilkwang weights](https://www.kaggle.com/datasets/pilkwang/rsna-knee-weights) | 4 | Популярность notebook не переносится автоматически на Dataset |
| [Bend the Knee to DinoV3](https://www.kaggle.com/code/mattiaangeli/bend-the-knee-to-dinov3-ensembled) | 210 | Применимый ансамбль и credits, но большой набор зависимостей |
| [Head and shoulders, knees and toes](https://www.kaggle.com/code/prvsiyan/head-and-shoulders-knees-and-toes) | 188 | Готовый ансамбль, на просмотренной странице best LB 0.936 |

Следовательно, «веса всегда собирают больше голосов» не подтверждается. Хорошая
ставка — новая полезная модель, понятная причина её использовать и полностью
готовый запуск. Высокий score, возраст публикации, авторская аудитория и удобство
смешаны; по этим наблюдениям нельзя оценить причинный вклад или прогноз votes.

В [обсуждении Raptor](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/discussion/737696)
автор сообщает: исходные 0.924, затем 0.927 при увеличении числа окон с теми же
весами; другие собственные варианты 0.936–0.938. Последние числа — заявления
автора об иных конфигурациях, а не проверенный score скачанного нами checkpoint.
SWA, по его сообщению, не давала стабильного выигрыша. Не делать SWA главным
публикационным обещанием без собственного результата.

Скачан актуальный [training-код Raptor](https://www.kaggle.com/code/dreaddevelopment/knee-mri-training-the-twelve-finding-model).
Он прямо требует принести собственный файл слабых меток: исходный label set не
поставляется. Есть также различие описаний геометрии: в training-докстринге 44
среза, в карточке публичных весов 64. Воспроизведение требует зафиксировать точный
checkpoint, preprocessing, window count и фактические входы; нельзя считать
текущий training-скрипт побитовой репродукцией исходного 0.924.

Просмотренный актуальный [Dinosaurs](https://www.kaggle.com/code/mattiaangeli/bend-the-knee-to-the-dinosaurs)
уже добавляет собственный CoAtNet с per-finding spatial head и attention по окнам.
Просто «мы тоже добавили attention» будет слабым отличием.

## Предлагаемая последовательность

### 1. Закрыть разрыв между CV и запускаемым решением

Не прерывать текущий Grok run. Сохранить полные OOF, маски, fold manifests,
checkpoint hashes и конечный результат. Собрать отдельный live-DICOM inference
для лучшей завершённой модели, не смешивая её автоматически с A0. Проверить
совпадение train/cache/inference pixels и выходов FP32/FP16; проверить пропуски
слотов, порядок UID, все 12 колонок и отсутствие константных fallback.

Измерить на Kaggle T4 достаточный фиксированный набор train-исследований с
разными размерами серий: wall-time включая decode, p50/p95 на исследование,
RAM/VRAM. Три example test studies не являются полноценным runtime benchmark.
Дальше — отдельно разрешённый пользователем standalone submission замороженного
кандидата. Это калибровочная проверка применимости ветки, не сетка LB blends.

### 2. Главный новый артефакт: Raptor-style с воспроизводимыми labels

Начинать собственное обучение с generic ImageNet-pretrained CoAtNet, сохраняя
Apache attribution Raptor-кода. Не стартовать CV-folds с чужого knee-checkpoint,
который уже обучался на этих же исследованиях: новый split не удаляет утечку
из pretrained weights. Публичные веса использовать как reference inference.

Зафиксировать одну геометрию и один architecture/head, затем сравнить:

- контроль: Pilkwang soft targets;
- изменение: median сырых Pilkwang + Steven v2 + Lixin, как описано в S12.
  Не использовать готовый blend как независимого teacher.

Это одна семантическая гипотеза: доверять согласованным свидетельствам нескольких
источников меток. Архитектура, геометрия, split, число шагов и inference одинаковы.
Первое сравнение — median без confidence weighting. Маску расхождений из S14
проверять отдельным последующим экспериментом. Любой технический фикс MixUp
применять одинаково в обоих arms.

Сначала один fold как screening с заранее заданным лимитом; затем 5 folds только
для контроля и выжившего варианта. Точное время оценить полным pilot-epoch на A100,
не переносить чужие часы на 4090 или скорость маленького ResNet на CoAtNet.
Зафиксировать общий reference metric для обеих label-версий. Он всё ещё может
предпочитать своего teacher, поэтому дополнить оценкой по настоящим labels:
для каждого gold study использовать только модель, не видевшую его в train;
не выбирать эпохи/гиперпараметры по этим же gold predictions. На 58 исследованиях
не настраивать 12 независимых коэффициентов и не обещать точность маленьких delta.

Если 11-GiB геометрия заметно ограничивает сильный backbone, разрешить отдельный
PRIVATE cache большей ширины покрытия/разрешения после прямого сравнения.
Предыдущий storage probe не доказывает оптимальность 224×9 для CoAtNet. Не
переключать геометрию чужих весов незаметно. Публикуются веса и код, не MRI cache.

### 3. Дешёвая независимая гипотеза для Grok

После текущей архитектурной серии вместо ещё одной смены backbone сравнить
узкое .35–.65 и широкое .10–.90 окно при тех же 224×9, crop 130, labels и folds.
Это предложение, не измеренный эффект. Отдельно смотреть MCL и lateral meniscus
(слабые классы S24), но решение принимать по общей метрике и заранее заданным
guardrails. Более редкие срезы создают большие физические разрывы, особенно для
3D convolutions; это риск. Для window-MIL тройки должны оставаться внутри
одной серии и группы соседних срезов. Нельзя склеивать тройки через границы слотов.

Эту ветку выпускать первой только если она сама показывает привлекательный
score/скорость либо добавляет воспроизводимый выигрыш к доступному baseline.
Не объявлять выигрыш от слабого OOF-ансамбля автоматически LB-выигрышем.

## Порог выпуска и формат

Ориентиры, не прогноз: standalone около 0.93+ при заметной простоте/скорости;
либо полный доступный inference около 0.937–0.94+ с измеримым вкладом новых весов.
Перед выпуском обновить сравнение с актуальными открытыми решениями. Если score
ниже, выпускать как training baseline с честным позиционированием, не «high-score».

Для доказательства: одинаковые исследования и reference labels; OOF delta,
paired study-bootstrap interval, fold deltas, повтор на втором seed для финалиста;
выбор лучшей эпохи и всего эксперимента раскрыт как ограничение. Сам bootstrap
не учитывает всю неопределённость обучения. Не подбирать параметры по LB;
разрешённый submission фиксирует фактический score конкретного артефакта.

Один Dataset: FP16/state_dict либо safetensors весов, model/preprocessing config,
порядок targets, requirements/версии, hashes, краткая MODEL_CARD, credits/license,
агрегированная ablation-таблица. Без MRI, отчётов, сырых label tables и validation
truth. Не упаковывать чужие веса без необходимости; ссылки на исходники сохранять.

Один основной notebook: только competition input + один пакет весов; `predict`
на live test DICOM, CPU decode и T4 inference, internet off, корректный
submission.csv при произвольном числе исследований. Режимы single/full допустимы,
но таблица должна показывать score/time каждого, без обещания неиспытанного режима.
Training/rebuild — отдельный запускаемый скрипт в пакете либо companion notebook,
с закреплёнными доступными labels. Три блока первого экрана: реальный LB и cost,
одно изменение, как запустить. Короткое доказательство: baseline → change, delta,
uncertainty, runtime. Название без SOTA до доказательства.

Формат весов и правила — разные уровни. Карточка Raptor указывает CC0, training
notebook Apache 2.0; при использовании сохранить provenance. Правила RSNA прямо
требуют публичные веса от победителей, что отличается от раздачи исходных MRI,
но лицензии исходных backbone и других зависимостей всё равно проверяются.
[Правила](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/rules).

Не запускать одновременно новую тяжёлую модель рядом с текущим Grok без общей
очереди. Этот документ не меняет S-ID, registry или активные процессы. Следующий
исполнитель сначала завершает текущий run и утверждает одну из вышеописанных
гипотез в экспериментальном плане. Никакие submissions в рамках анализа не делались.
